# Project Requirements Document (PRD)
## TapNex AI Customer Support Agent (RAG System)

### 1. Introduction
The TapNex AI Customer Support Agent is a specialized system built using a Retrieval-Augmented Generation (RAG) architecture. Its primary purpose is to assist event organizers and attendees by answering queries based strictly on the TapNex company knowledge base. TapNex is an event technology platform that provides NFC-based payment systems and event infrastructure. 

### 2. Objectives
*   Provide accurate, context-aware answers to user inquiries regarding TapNex services, payment systems, ticketing, and policies.
*   Ensure the AI strictly adheres to the knowledge base, returning structured "I don't know" responses for out-of-scope or irrelevant queries.
*   Demonstrate a working RAG pipeline consisting of document loading, splitting, embedding, vector storage, and an LLM for generation.

### 3. Architecture & Tech Stack
The solution uses modern, lightweight tools optimized for speed and accuracy:
*   **Frontend / Interface:** Streamlit (Provides an interactive, chat-based web UI)
*   **Orchestration Framework:** LangChain Core (Handles document loading, vector storage, custom prompt chains, and LLM communication)
*   **Embeddings & Vector Database:** 
    *   *Embeddings:* `HuggingFaceEmbeddings` model `all-MiniLM-L6-v2` run locally. This completely eliminates costs related to embeddings and keeps document processing fully private.
    *   *Vector Store:* `FAISS` (Facebook AI Similarity Search) to store document embeddings in RAM for exceptionally fast retrieval.
*   **Large Language Model (LLM):** Groq API utilizing the `llama3-8b-8192` model. This model ensures fast streaming responses and high accuracy with strict system prompt adherence.

### 4. Implementation Details
#### 4.1 Knowledge Base Processing
*   The raw text from the `knowledge_base.txt` file is ingested using LangChain's `TextLoader`.
*   A `RecursiveCharacterTextSplitter` breaks the text down into chunks of 500 characters with an overlap of 50 characters, ensuring relevant context is never sliced inappropriately.

#### 4.2 Retrieval System
*   Document chunks are mapped into continuous vector space using the local HuggingFace embedding model.
*   FAISS performs a similarity search (`k=3`) to retrieve the 3 most relevant context chunks for any incoming user query.

#### 4.3 AI Response Generation
*   The retrieved context chunks are combined and injected into an engineered System Prompt.
*   The System Prompt strictly instructs the Llama3 model:
    > "Answer user queries accurately based ONLY on the provided context below. If the user asks a question that is unrelated to TapNex or not present in the context, you MUST reply EXACTLY with: 'I'm sorry, I couldn't find that information in the TapNex documentation.'"
*   The response generated by the Groq-powered LLM is displayed in the Streamlit application's user interface.

### 5. Running the Application
1.  **Clone / Download** the repository to your local machine.
2.  **Create a Virtual Environment** and install dependencies using:
    `pip install -r requirements.txt`
3.  **Environment Variables:** Copy `.env.example` to `.env` and provide your Groq API Key: `GROQ_API_KEY=gsk_xxxxxxxxxxxxxxx`
4.  **Run the application** via Streamlit:
    `streamlit run app.py`

### 6. Verification Criteria Met
*   **Knowledge Base Parsing:** Handled via custom chunking strategy.
*   **Query Input:** Streamlit provides a seamless chat interface.
*   **RAG Functionality:** FAISS + Local Embeddings reliably extracts context.
*   **Guardrails:** Irrelevant questions (e.g., "Who is Elon Musk?", "Capital of France?") are handled effectively due to rigid prompt engineering.
